# Análise dos repositórios e estratégia do portfólio

## Projetos em destaque

### 1. ZeroInsight
É o projeto mais forte do perfil. Demonstra arquitetura full-stack, integração com IA, múltiplos providers, FastAPI, React, Electron, Expo, empacotamento, segurança e preocupação com fluxo de produto. Deve permanecer como projeto principal.

### 2. QA Platform
Conecta diretamente o código com a experiência profissional em QA. Tem uma proposta clara, boa documentação e cobre gestão de testes, bugs, acessibilidade, performance e verificações de segurança. Deve ser apresentado como plataforma local/protótipo, não como scanner capaz de substituir ferramentas profissionais.

### 3. Mechanic Site
É a melhor evidência pública de aplicação web tradicional completa: frontend React, backend Express, autenticação, banco relacional, calendário e regras de negócio.

### 4. ZeroCoding
Mostra capacidade de criar tooling para desenvolvedores, trabalhar com modelos locais, abstração de providers, sessões, contexto explícito e interface de terminal.

### 5. ZeroSpecter
É relevante para o eixo de segurança, mas deve ser descrito como projeto de aprendizado e toolkit para ambientes autorizados. Evitar promessas amplas de “ferramenta profissional de pentest” sem testes e manutenção que sustentem essa afirmação.

### 6. Site Requisite
Demonstra implementação de identidade visual, componentes reutilizáveis, CSS Modules e entrega voltada a negócio real.

## Repositórios que não devem ocupar o primeiro plano

- Repositórios vazios ou quase vazios, como ZeroFocus, Fenrir e ZeroShield no estado atual.
- Experimentos mínimos ou projetos sem README próprio.
- Variações duplicadas, como ZeroSpecterC, enquanto não houver implementação suficiente para justificar um projeto separado.
- Repositórios de treinamento sem uma entrega diferenciada.

Eles podem continuar públicos, mas não devem competir visualmente com os projetos mais maduros.

## Correções feitas na narrativa

- O estágio foi apresentado como QA e software, não como estágio puramente backend.
- A experiência em segurança foi descrita como trabalho autorizado e baseado em evidências.
- O site não afirma domínio avançado de Assembly ou sistemas de baixo nível sem evidência pública suficiente.
- A stack foi agrupada por capacidade e problema resolvido, em vez de uma parede de logotipos.
- Projetos privados ou ainda não publicados, como ZeroHub e sistemas internos da Requisite, aparecem apenas de forma indireta na experiência, sem links falsos.

## Próximas melhorias recomendadas nos repositórios

1. Adicionar screenshots ou GIFs ao ZeroInsight, QA Platform, Mechanic Site e ZeroCoding.
2. Configurar tópicos, descrição curta e homepage em todos os projetos destacados.
3. Adicionar CI mínimo com lint e testes.
4. Corrigir links absolutos locais no README do ZeroCoding.
5. Criar um README real para o Mechanic Site, com arquitetura, setup e imagens.
6. Arquivar ou tornar privados repositórios vazios que não fazem parte de um roadmap público.
7. Fixar no perfil os seis projetos usados no portfólio.
